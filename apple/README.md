# Lynx Reminders — Apple client

macOS (primary) and iOS/iPadOS from one SwiftUI code base. The contract is `../docs/SPEC.md`.

```
apple/
  Package.swift            LynxKit: LynxCore (pure Foundation) + LynxSync (supabase-swift 2.55.6)
  Sources/LynxCore/        models, JSON store, repeat rules, notification planner, sync engine,
                           trigger matching, smart lists, quick add
  Sources/LynxSync/        Supabase RemoteStore, auth (session in the Keychain), sharing RPCs, realtime
  Tests/LynxCoreTests/     every vector in ../shared/vectors/recurrence.json + sync/trigger/list/quick-add tests
  Tests/LynxSyncTests/     live tests against the local Supabase (opt-in)
  App/Shared/              SwiftUI app for both platforms (platform bits behind #if os(...))
  App/macOS/               menu bar extra, IOBluetooth + NSWorkspace triggers, launch at login, commands
  App/iOS/                 FireTriggerIntent (App Intent for Shortcuts automations)
  Resources/               Onest + Geist Mono, asset catalog (Etherlynx griffin mark), AppIcon.icon (Icon Composer, generated by shared/icon/build-icons.sh)
  Config/Supabase.json     {"url", "anon_key", "passkey_page"} bundled into the app
  project.yml              XcodeGen spec → LynxReminders.xcodeproj (both are kept in the repo)
  build.sh                 macOS build with ad-hoc signing → build/Lynx Reminders.app
```

## macOS: build and run

Needs Xcode 26 (Swift 6.2). No Apple developer account: the app is signed ad hoc.

```sh
cd apple
./build.sh                         # Release; CONFIG=Debug ./build.sh for a debug build
open "build/Lynx Reminders.app"
```

`build.sh` regenerates the project with XcodeGen when it is installed (`brew install xcodegen`); otherwise it
uses the committed `LynxReminders.xcodeproj`. You can also open the project in Xcode and run the
`LynxReminders-macOS` scheme.

Data lives in `~/Library/Application Support/com.mansfera.lynxreminders/` (`store.json` = synced rows +
dirty marks, `device.json` = local-only cooldowns, snoozes, region states). The session is in the Keychain,
service `com.mansfera.lynxreminders`.

The app keeps running in the menu bar when the window is closed, so location, Bluetooth and app triggers keep
working; turn on *Open at login* in Settings (⌘,). Shortcuts: ⌘N new reminder (focuses quick add), ⇧⌘N new
list, ⌘F search, ⌘↩ or space complete, ⌘⌫ delete, ⌘1–4 Today/Scheduled/All/Flagged.

**Server.** `Config/Supabase.json` points at the local stack (`http://127.0.0.1:54321`, demo anon key). For a
hosted project replace both values and rebuild. If the file is missing or the server is unreachable the app works
fully local; signing in later uploads local lists and reminders.

**Demo data / screenshots.** `LYNX_DATA_DIR=<scratch folder> LYNX_DEMO=1` fills an empty scratch store through
the same calls the UI makes (it never touches your real data or Keychain; the session goes to
`<scratch>/session.json`). `LYNX_SCREEN=today|list:<name>|reminder:<title>|smart:<name>|signin|welcome`,
`LYNX_APPEARANCE=light|dark`, `LYNX_DEMO_SIGNUP=1` (creates a throwaway account and syncs).
`Tools/screenshot.sh out.png light "list:Trip to Vienna"` launches it that way and captures the window.
Launch with `open --env …` (as the script does), not by running the binary from a terminal: macOS then attributes
the Bluetooth/location permission request to the terminal, which has no usage string, and kills the app.

**Which backend.** Builds use the hosted project in `Config/Supabase.json`. To build against the
local stack instead, put its URL and key in `Config/Supabase.local.json` (git-ignored); `build.sh`
bundles that file when it exists. A copy for the local stack is kept as `Config/Supabase.local.off.json`.

**Notifications after demo runs.** Demo data schedules real alerts. To remove them, launch once with
`open -n --env LYNX_DATA_DIR=<empty folder> --env LYNX_CLEAR_NOTIFICATIONS=1 "build/Lynx Reminders.app"`, then quit:
every launch removes all pending alerts, and the switch also empties Notification Center. Add
`--env LYNX_NOTIFICATION_REPORT=<file>` to write what macOS still holds for the app before and after.

This only reaches alerts from builds made by `build.sh` since 17 Nov. macOS files notifications per
code signature, and an ad-hoc signature is normally tied to one exact binary, so each earlier rebuild
counted as a separate app: alerts it scheduled kept firing and no later build could see or remove them.
`build.sh` now signs with a designated requirement on the bundle id, so every rebuild shares one
identity. Builds from Xcode's own Run button are still signed per binary.

## Tests

```sh
cd apple
swift test                                        # LynxCore: all recurrence vectors + sync/trigger/list/quick-add
LYNX_LIVE=1 swift test --filter LiveBackendTests  # against the local Supabase from ../backend
```

The vector file is read from `../shared/vectors/recurrence.json` relative to the test source (`#filePath`), so
regenerating the vectors with `python3 shared/reference/recurrence.py` is picked up without copying.
The live tests sign up throwaway users (in-memory session, no Keychain), sync, share, revoke, check realtime and
the email-code sign-in through Mailpit (`http://127.0.0.1:54324`), and delete the users at the end.

## iOS / iPadOS

The iOS target (`LynxReminders-iOS`) shares every screen; `NavigationSplitView` collapses to a stack on iPhone.

Compile check without a device or account:

```sh
xcodebuild -project LynxReminders.xcodeproj -scheme LynxReminders-iOS \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

That needs the iOS platform component (Xcode → Settings → Components). Without it, `Tools/ios-compile.sh` builds
the target for the simulator SDK directly (skipping only the asset catalog, whose compiler needs a runtime).

### Running on a device once there is a paid developer account

1. In `project.yml` set `DEVELOPMENT_TEAM: <your team id>` (base settings) and remove the macOS-only
   `CODE_SIGN_IDENTITY: "-"` / `CODE_SIGN_STYLE: Manual` if you want Xcode-managed signing on the Mac too;
   run `xcodegen generate`.
2. Bundle id stays `com.mansfera.lynxreminders` (register it in the developer portal; Xcode can do it).
3. Capabilities:
   - **Location**: nothing to add in the portal; the usage strings are in Info.plist. For region monitoring
     with the app closed, iOS asks for *Always* after *While Using*.
   - **Push notifications**: later, only if server-sent pushes are added (local notifications need nothing).
   - **App Groups**: only if a widget or extension needs the store; then move the data folder into the group
     container (`FileManager.containerURL(forSecurityApplicationGroupIdentifier:)`).
   - **Keychain sharing**: only if a future extension needs the session.
   - **Sign in with Apple** (SPEC §9 "later") needs the capability and a Services ID.
   - **Associated Domains** `webcredentials:reminders.etherlynx.xyz` plus `web/public/.well-known/apple-app-site-association`
     with the team id lets passkeys use the native prompt (`ASAuthorizationPlatformPublicKeyCredentialProvider`,
     or supabase-swift's `signInWithPasskey(presentationAnchor:)`) instead of the passkey page in a browser sheet
     (SPEC §9). Existing passkeys keep working.
4. The Mac app can then be signed with the team too (hardened runtime + notarization for distribution;
   add `com.apple.security.device.bluetooth` and `…personal-information.location` entitlements if you sandbox it).
5. For the hosted backend set `Config/Supabase.json`; a device cannot reach `127.0.0.1` on your Mac.

## Platform limits (SPEC §6.1)

| trigger | macOS | iOS / iPadOS |
|---|---|---|
| time / repeat / nag | UNUserNotificationCenter | same |
| location arrive/leave | CLMonitor while the app runs (keep it in the menu bar, launch at login) | CLMonitor; the system wakes the app; at most 20 regions → the nearest 20 |
| Bluetooth connect/disconnect | IOBluetooth notifications while the app runs | not observable by apps: a Shortcuts automation "Bluetooth → Run *Fire Lynx trigger*" (in-app guide) |
| app opened | NSWorkspace `didActivateApplication` | not observable: Shortcuts "App is opened → Run *Fire Lynx trigger*" |

Every device evaluates triggers on its own; a context trigger fires once per reminder per 15 minutes
(local cooldown) and starts the nag if one is set. Notifications are planned from the store after every edit,
sync, launch and activation, capped at the 60 soonest (iOS allows 64 pending; 4 are left for snoozes).
